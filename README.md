# IdeaMix — от идеи к реальности

IdeaMix — полноценная веб-платформа на Django, где участники публикуют идеи,
собирают команды и превращают замыслы в проекты. Интерфейс полностью
русскоязычный, адаптивный и построен на Django Templates без React/Node.

## Возможности

### Идеи
- Создание, редактирование и удаление идей с черновиками и статусами
  «Черновик», «Опубликована», «В работе», «Реализована».
- Публичная и приватная видимость: приватная идея доступна автору и участникам
  связанных проектов.
- Короткое и полное описание, категория, до 5 тегов, обложка.
- Каталог с поиском по названию, описанию, тегам, автору и категории,
  фильтрами по категории/статусу/тегу и сортировкой по новизне, лайкам,
  просмотрам.
- Пагинация, пустые состояния, скелетон-загрузка при фильтрации.
- Счётчик просмотров (один просмотр на идею в рамках сессии).

### Взаимодействие
- AJAX-лайки и добавление в избранное с graceful degradation без JavaScript.
- Комментарии: добавление, редактирование и удаление автором.
- Избранное и страница «Мои идеи» с фильтром по статусу.
- Копирование ссылки, тосты, модальные окна подтверждения.

### Проекты и команды
- Создание, редактирование и удаление проектов.
- Статусы проекта, видимость, открытый/закрытый набор участников.
- Технологии, нужные специалисты, ссылки на репозиторий и демо.
- Привязка идеи-основы и добавление собственных идей в проект.
- Участники с ролями: владелец, разработчик, дизайнер, исследователь,
  другой специалист.
- Присоединение к открытому проекту, выход из команды, управление ролями,
  добавление и удаление участников создателем.
- Приватный проект виден только создателю и участникам.

### Аккаунты
- Регистрация с проверкой уникальности логина и email.
- Вход/выход, безопасный редирект после входа.
- Профиль с аватаром, биографией, городом, сайтом и навыками.
- Редактирование профиля и смена пароля.
- Публичный профиль с вкладками «Идеи», «Проекты», «Команды»; владелец
  дополнительно видит «Избранное», черновики и приватные идеи.

### Оформление
- Светлая и тёмная темы с переключателем в шапке.
- Выбор темы сохраняется в браузере; при первом визите учитывается системная
  настройка `prefers-color-scheme`.
- Тема применяется до отрисовки страницы, поэтому интерфейс не мигает.

### Администрирование и качество
- Настроенная админка для всех моделей: фильтры, поиск, действия,
  превью статусов, автоматические счётчики.
- Стартовая панель «Пульс платформы»: пользователи, идеи, проекты,
  комментарии, лайки, избранное, категории и динамика за 7 дней.
- График онлайна за 7 дней: уникальные авторизованные пользователи в сутки,
  «онлайн сейчас» и пик недели. Присутствие собирает middleware и хранит
  агрегаты в `UserActivity` (одна строка на пользователя в день).
- Готовый суперпользователь с полным доступом и безопасная management-команда
  `create_admin`, которая создаёт администратора только при его отсутствии.
- Идемпотентная команда `seed_ideamix` для наполнения базы реалистичными
  демонстрационными данными (категории, пользователи, идеи, проекты, связи).
- Серверная проверка прав на каждом изменяющем действии.
- Валидация загружаемых изображений (расширение, MIME-тип, размер).
- Фильтр нецензурной лексики для идей, проектов, комментариев, профилей,
  категорий, имён и логинов.
- CSRF-защита, безопасные настройки cookie, HSTS/HTTPS при `DEBUG=0`.
- Кастомные страницы ошибок 400/403/404/500.
- 127 автоматических тестов: права, CRUD, фильтры, AJAX, комментарии,
  проекты, роли, шаблоны, тема оформления, фильтр мата, админ-панель,
  график онлайна, команды администратора и демонстрационных данных, отсутствие N+1.

### Модерация
- Фильтр мата включён по умолчанию и проверяет пользовательский текст на
  сервере до сохранения — и в обычных формах, и в Django Admin.
- Нормализация обходит простое маскирование: `ё → е`, латинские похожие
  буквы, цифры и символы вместо букв (`6`, `@`, `*`), повторяющиеся буквы.
- Проверяются русские корни и формы, английские слова и латинские
  транслитерации; безопасные слова вроде «хлеб», «себе», «небо», «сукно»,
  «бляха» и «команда» не блокируются.
- Отключается переменной `IDEAMIX_PROFANITY_FILTER=0` (не рекомендуется
  в production).

## Технологии

- Python 3.12+ (проект проверен на Python 3.14)
- Django 5.2 LTS
- SQLite
- Django ORM, auth, forms, messages, paginator, admin
- Django Templates, HTML5, CSS3, JavaScript (ES5-совместимый progressive enhancement)

## Установка

### 1. Виртуальное окружение

Windows (PowerShell):

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 2. Зависимости

```bash
pip install -r requirements.txt
```

### 3. Переменные окружения

Скопируйте `.env.example` в `.env` и задайте свой секретный ключ:

```powershell
Copy-Item .env.example .env
```

```bash
cp .env.example .env
```

Сгенерировать ключ:

```bash
python -c "from django.core.management.utils import get_random_secret_key as k; print(k())"
```

Если `DJANGO_SECRET_KEY` не задан и `DEBUG=1`, проект создаст локальный
`.secret_key` автоматически. В production ключ обязателен.

Фильтр нецензурной лексики включён по умолчанию. Отключить его можно только
явно:

```dotenv
IDEAMIX_PROFANITY_FILTER=0
```

### 4. Миграции и администратор

Сначала примените миграции:

```bash
python manage.py migrate
```

Стандартный способ создания администратора:

```bash
python manage.py createsuperuser
```

Django последовательно запросит логин, email и пароль. Пароль вводится скрыто,
хранится только в виде хеша и не выводится в консоль.

Дополнительная команда проекта:

```bash
python manage.py create_admin
```

Она интерактивно запрашивает логин, email и пароль (или принимает
`--username`, `--email` и `--password`). Пароль проверяется стандартными
валидаторами Django и сохраняется штатным механизмом хеширования. Команда
создаёт только нового администратора:

- если суперпользователь с таким логином уже существует, его пароль, email и
  права не изменяются;
- если логин занят обычным пользователем, команда завершается с понятной
  ошибкой, не повышая его права;
- пароль никогда не записывается в исходный код и не выводится в логи;
- повторный запуск не создаёт дубликаты.

Для автоматизации можно передать пароль через переменную окружения
`DJANGO_SUPERUSER_PASSWORD` (не через `--password`, чтобы он не остался в
истории команд).

В текущей локальной базе уже создан администратор:

- логин: `max`
- email: `max@ideamix.local`
- пароль выдан отдельно при настройке проекта — смените его после первого
  входа в разделе «Пароль» или командой `python manage.py changepassword max`

### 5. Демонстрационные данные

После миграций базу можно наполнить реалистичными данными:

```bash
python manage.py seed_ideamix
```

Команда создаёт 10 категорий, 15 демонстрационных пользователей, 20 идей,
10 проектов, участников проектов, 30 комментариев, 40 лайков и 15 записей
избранного. У пользователей `demo_*` нет прав администратора, а пароль
недоступен для входа (unusable password). Изображения не подставляются,
поэтому фиктивных ссылок на файлы нет.

Все операции выполняются в одной транзакции и используют безопасные проверки
существующих записей. Повторный запуск не создаёт дубликаты и не удаляет
данные. Если запись уже существует, она сохраняется без перезаписи; профили
демонстрационных пользователей обновляются до актуальных значений.

### 6. Запуск

```bash
python manage.py runserver
```

Откройте <http://127.0.0.1:8000/>. Административная панель доступна по
адресу <http://127.0.0.1:8000/admin/>.

В текущем окружении используется локальное виртуальное окружение `.venv`:

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_ideamix
.\.venv\Scripts\python.exe manage.py runserver
```

## Безопасность

- Все изменяющие запросы требуют CSRF-токен; выход и реакции принимают
  только POST.
- Права проверяются на сервере: автор идеи, автор комментария, создатель
  проекта.
- Приватные идеи и проекты не попадают в публичные выборки и возвращают 404
  при прямом обращении.
- Загрузки ограничены по расширению, MIME-типу и размеру (аватар — 2 МБ,
  обложка — 5 МБ).
- Пароли проходят стандартные валидаторы Django.
- Нецензурная лексика отклоняется серверными валидаторами моделей и форм;
  фильтр также действует в Django Admin. Отключается только явной настройкой
  `IDEAMIX_PROFANITY_FILTER=0`.
- Секреты хранятся в `.env` / `.secret_key` и исключены из Git.

## Production

1. Установите `DJANGO_DEBUG=0` и задайте `DJANGO_SECRET_KEY`.
2. Укажите реальные `DJANGO_ALLOWED_HOSTS` и `DJANGO_CSRF_TRUSTED_ORIGINS`.
3. Настройте HTTPS: при `DEBUG=0` включены редирект, secure cookies и HSTS.
4. Выполните `python manage.py collectstatic`.
5. Раздавайте `staticfiles/` и `media/` через веб-сервер или object storage.
6. Для высокой нагрузки замените SQLite на PostgreSQL и настройте почтовый
   backend.

## Известные ограничения

- Проект использует SQLite — достаточно для локальной работы и небольших
  инсталляций; для production рекомендуется PostgreSQL.
- Поиск работает через `icontains` SQLite и не использует полнотекстовый
  индекс; для больших объёмов данных стоит подключить PostgreSQL Search
  или Elasticsearch.
- Загрузка изображений хранится локально в `media/`; нет интеграции с S3.
- Нет email-подтверждения, восстановления пароля и уведомлений — письма
  выводятся в консоль.
- Нет OAuth/социального входа. Модерация автоматическая: фильтр ловит мат и
  частые маскировки, но не заменяет ручную проверку и не распознаёт текст на
  изображениях; специально разнесённые по буквам слова могут не отловиться.
- Пагинация и фильтры обновляют страницу; AJAX используется для лайков,
  избранного и вспомогательных действий.
- В проекте нет демонстрационных данных: статистика и счётчики отражают
  только реальные записи в базе.
